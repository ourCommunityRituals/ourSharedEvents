## 1. Five most dangerous assumptions

1. **A: "no stored or logged value outside the scan tables pairs a visitor's key with a place, or carries a clock finer than the hour" - FALSE as worded.** `forms.ts:302` stores `source_placement_id` beside `anonymous_id`. `shared-report.ts:278-289` stores `anon_id_hash` beside `venue_id` with ms stamps. `wrangler.toml:95-96` `[observability] enabled = true` on defaults keeps a platform request log (the /q/<token> URL plus time); S3 defers this (F-15) yet A is absolute. `shortlink_click_daily` (migration 0094, `shortlinks.ts:378`) is a stored day-grain tap cell the subject never mentions.
2. **A/S16/H: "every scan figure is a sum of the same poster-hour cells" - FALSE on main today; A says it depends on OSE-1784, but S16 para 1, H ("admin cells and report now one figure") and S15 read as present tense.** `shared-report-builder.ts:321-346` `distinct_scanners` sums event-hour `scan_aggregates` (not poster-hour); taps are lifetime `SUM(clicks)` (`dashboards.ts:276-280`). Worked case: poster A 3 + poster B 3 people in one hour withholds both poster-hours, yet the event-hour distinct cell is 6 and is published.
3. **S6: "the tables gain no shared durable correlation key; the spike can show or refute it" - FALSE / the test cannot discriminate.** Both rows are written in one batch (`scan-buffer.ts:101-137`); rowid is max+1 in each table. Model (in-memory SQLite, schema of 0062+0101, 12 distinct browsers, 2 posters): rank join on (event, hour) recovered the poster for 12 of 12 browsers. A browser scanning two posters in one hour leaves 5 placement rows but 4 return rows (0101 unique index), so a naive predictor misaligns.
4. **S4: "a sealed cell cannot change" - TRUE only for `scan_placement_events` on the direct path; FALSE for `scan_cell_aggregates`; ASSUMED for production staying queueless.** Direct path: bucket is the request-time hour (`qr-scan.ts:165,190`), so G=15 min vs seconds of delay. Stored cells are a daily 03:00 UTC DELETE+INSERT snapshot (`wrangler.toml:105`, `shared-report.ts:879-905`): the hour open at the cron is stored partial. A read-time bound on `bucket_hour` does not prove `computed_at` >= seal. Production queue is a dark build (`wrangler.toml:358-362`); the "revisit" trigger is a sentence, not a gate.
5. **S3/H: "taps have no time bucket" and "Timing within the hour: A: S4" for every actor - FALSE for taps and check-ins.** Tap and check-in totals stay live (S4 AC4 admits it) and cross the floor in the minute; memo R4 says live views need separate noised treatment (memo lines 127-135). `last_clicked_at` has no reader in `src/` (TRUE, grep), so the day coarsening is safe but low value.
