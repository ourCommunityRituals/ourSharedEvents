## 2. SharedReport: what it draws, and what it would need

**How it is served.** The page is a static template that sets `no-store` and `Referrer-Policy: no-referrer` (`pages.ts:3119-3135`). The browser then asks for the data with the link's token as a bearer. The token is never kept in a cookie or in storage.

**Who × plan, on every read** (`src/handlers/shared-report-read.ts:80-230`):

1. No token, a bad token or the wrong event: 401 or 403 before anything is built.
2. Depth by role: `resolveDepth` (`src/lib/report-depth.ts:122`). A sponsor is capped at Mid; an unknown claim falls to Local.
3. Plan: `capDepthToPlan` (`shared-report-read.ts:133`, `report-depth.ts:164`). The plan lookup fails closed: an error reads as "no paid report" (`src/lib/feature-flags.ts:181-191`).
4. The report is cut to that depth by `filterReportByDepth` (`shared-report-read.ts:214`). **The map (`corridor_map`) exists only at Mid and above** (`report-depth.ts:65`, `:82`). A Free reader gets no map.

**The map it draws today** (`shared-report-builder.ts:827-930`, `src/lib/corridor-map.ts`):

- One hexagon per poster placement, at res 9, valued by scans there (not people). A poster-hour under 5 never joins a sum (`:877-890`); a cell under 5 is dropped before drawing (`:899`), never drawn as an outline.
- If poster cells exist and none reaches 5, no map at all (`:916-920`).
- With no poster data: the event's res-7 cell with the floored count of people, and its six neighbours as dashed outlines (`:921-930`).
- The SVG is drawn in an equirectangular frame with the longitude scaled by latitude (`corridor-map.ts:76-94`), with raw colours (`#4361ee`, `#5a5a5a`, `#b9b4ab` at `corridor-map.ts:65`, `:70`, `:106`) and each cell's exact count in `data-count` (`:112`).
- It imports nothing from `street-map.ts`, `attendee-map.ts` or `map-areas.ts`.

**What is written about a street layer there.** `docs/positioning/MAPPING-COST-STRUCTURE.md:35` says SharedReport draws hexagons only. Line 86 of the same file says the Mid report's corridor map is the paid line and "the street-map layer lands here first". No ADR decides it. So putting streets under the report changes a written line: it needs the owner's ruling (proposed in OSE ADR-036, this pull request).

## 6. Solution design

### 6.1 One door, cells only

Every surface asks `loadStreetLayer(env, cells, opts)` and gets a layer or null. That stays the only way to streets. No surface reads tiles, and no route serves a tile (ADR-033, alternative B). What goes in is cell ids and nothing else: no event id, no token, no count, no viewer position. The frame, the tiles, the drawing and every cache key are functions of the cells, the archive and the drawer's code. So a street layer can never say more than its cells already say, and the same layer is right for every reader.

Three small additions to that door, none of which changes a rule:

- `opts.surface`: a fixed word (`landing`, `zoom`, `areas`, `report`) used only for the outcome counter (6.6).
- the layer's outcome, kept beside the layer: `drawn`, `none` (no binding, no object or no tile), `wide`, `thin`, `slow`, `error`.
- for the report, the caller passes the res-7 parents of its shown cells as the frame and the shown cells as the ones to keep labels clear of (the `numbered` option that the area route already uses).

### 6.2 The reader (`lib/pmtiles.ts`)

1. **Nothing a request waits on belongs to another request.** The module-scope cache keeps settled values (the header, the root directory, decoded leaf directories), never a pending promise. Within one frame's read the pending work is still shared, in a map that lives for that call. Two requests that arrive together in a cold isolate each open the archive once; that costs one extra 16 KB read, once in an isolate's life, and removes the lost-race question. To be proved red first in the workers pool (slice B1); if the runtime shows the present code safe, the test stays as the proof and the code stays.
2. **The object's etag rides on every read.** The first read records the object's `etag`. Every later range read passes `onlyIf: { etagMatches }`. An answer with no body means the object changed: the reader forgets that archive and throws, this request draws hexagons only, and the next one opens the new object clean (slice B2). No extra request is made.
3. **A missing object is remembered for a short time** (30 seconds, in the isolate), so an unloaded key costs one read every 30 seconds per isolate and not one per page (slice B2). The time comes from `Date.now()`, which moves on I/O; a request always does I/O first.
4. **A pinned etag** (`MAP_TILES_ETAG`, optional): when set, an object with another etag is refused at open. The code can land now with the setting empty. The value is known only after the load, so setting it is the owner's (O3).

### 6.3 Bounded work

- A cap on features per layer and on points per tile while decoding, and on points projected per frame, so the work before the 9,000-point budget is bounded by count (slice B3). The numbers come from the real tiles already measured: the densest frame asked for about 97,600 points, so a frame cap of a few times that refuses nothing real. Over the cap the tile is refused and the frame draws hexagons only, the way an oversize tile is refused today.
- `[limits] cpu_ms` in `wrangler.toml` as the last line of defence: an owner decision, because the right number depends on the plan and on every other route (question 1).
- The 1.5 s limit stays the bound on waiting. It is not a bound on CPU, and the design does not treat it as one.

### 6.4 Caching: what is kept, where, and for how long

| Tier | What is kept                                                    | Key                                                                                                        | Lifetime                                                                                                                                                            | Decision needed        |
| ---- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 0    | Header and directories, in the isolate (exists)                 | archive key, and its etag after B2                                                                         | The isolate's life; 64 leaves and 300,000 entries at most                                                                                                           | None                   |
| 1    | Drawn layers, in the isolate (slice B6)                         | archive key, etag, drawer version, frame size, sorted cells, the cells that carry a number                 | The isolate's life; a byte budget (a layer is about 100 KB; 32 layers is about 3 MB), oldest out first                                                              | None                   |
| 2    | Drawn layers, at the edge (slice O1)                            | The same, as a made-up address on a host that does not exist, the way `handlers/venue-image.ts:77-80` does | Long (30 days): the key names an object that is never overwritten and a drawer version, so an entry can never be stale. A refresh or a drawer change makes new keys | **Owner** (ADR-036 D5) |
| 3    | The area route's whole answer, for readers (exists, ADR-033 D5) | The address                                                                                                | One hour, and a day stale                                                                                                                                           | None today             |

**Why tier 2 is the owner's.** Two stores exist. The Cache API holds what the Worker puts in it; each data centre has its own copy; it has no stale-while-revalidate; and Cloudflare's page says it is not available for Workers fronted by Cloudflare Access, without saying which setup it means. Production is to be closed by an Access policy over the whole host (AGENTS.md, "Held, not closed"). So tier 2 may do nothing on production while it is closed, and nobody knows until it is tried on staging. Workers Cache keeps whole responses and suits the area route only; it is new, it needs a newer Wrangler than may be pinned, and it changes how every route of the Worker is billed. The design does not depend on tier 2: tiers 0 and 1 remove the repeat work inside an isolate, and tier 2 is an optimisation to measure after the load.

**What must never be stored anywhere:**

- A SharedReport answer or page: it depends on who is asking and on floored counts. `no-store` stays.
- A composed map: hexagons with their opacity, numbers, dots or counts. Only the street layer alone is stored.
- Anything keyed by an event id, a token, a brand or a count.
- A layer for cells that were not shown. For the report the key holds the res-7 parents of the shown cells, so a stored entry is the same entry the landing's zoomed view makes for that area and says nothing about the report.
- A null. A missing layer is remembered only as "the object is missing" for 30 seconds (6.2); a slow or failed draw is not remembered at all.

The landing page itself is not cached by this design. It depends on the event list and the search, and caching it is a separate question nobody asked.

### 6.5 Batching

- **Within a frame** (exists): one read plan for all tiles; neighbours joined across gaps up to 256 KB and 2 MB a read (`pmtiles.ts:365-367`); tiles of one run read once.
- **Between frames in one isolate** (exists, plus tier 1): directories shared; drawn layers shared after B6.
- **Several frames in one request** (new, only with a consumer): one function that takes several cell sets, opens the archive once, reads each distinct tile once, draws each frame, and holds all of it to one deadline. It is needed only if the batch report read carries streets. Until the owner rules on O2, the batch read carries none and this is not built.
- **No public route draws more than one frame.** The area route stays one frame a request; its limiter is the control.

### 6.6 Signals

One aggregate line a request, on the cost metric that already exists (`src/lib/cost-metric.ts`): the street outcome word, the number of R2 reads and the bytes read. No cell, no key, no address. The metric's key list is sealed by `tests/e2e/0-architecture/cost-metric-never-who.invariant.spec.ts`; adding three keys to it is a change to a security gate and goes through the Dr of Security in its pull request (slice B5). CPU time is already in each invocation's log line. After the load, a scheduled probe on staging asks for one known frame and fails by name when it has no roads (CCR R4): it needs the archive, so it follows the owner's load.

### 6.7 SharedReport on the base map (proposed; nothing here is built without the owner's ruling)

1. Who × plan decides first, exactly as today. The builder and the depth filter are not touched.
2. If, and only if, the answer still holds a live map after the filter, the read handler asks the base map for the layer of the res-7 parents of the shown cells.
3. The report's hexagons are projected with the base map's frame (N1), in tokens (N5).
4. The layer, its CSS and the credit travel in the same JSON answer, in the map object. The page mounts them in its map slot. No second request, no cell in an address.
5. A null layer leaves today's map, whole. A street failure changes nothing else in the answer.
6. The batch read carries no streets.
7. The answer stays `no-store` with `Vary: Authorization`.

### 6.9 Security, in one place

- **What a public caller can make the Worker read:** on the area route, 12 tiles and at most a handful of ranged reads a request, 360 requests a minute an address; on the landing, only frames the listed events make. No caller can name a tile, a byte range, a key or a bucket.
- **What a public caller can make it spend:** CPU for decode and draw, bounded today by bytes and after B3 by count.
- **What a hostile archive can do:** every length is checked before it is asked for and gzip stops at a limit (`pmtiles.ts:15-21`, `:206-232`); text from a tile is escaped; after B2 a swapped object is noticed. Who may write the bucket is ADR-035's open question, unchanged here.
- **What the map can say about a person:** nothing. It is drawn from cells. The report's layer is asked for after the floor, for shown cells' parent areas only.
- **What is logged:** an outcome word and two numbers.

## 8. Decisions only the owner can make

Carried from the CCR and still open: its questions 1 (plan and CPU limit), 2 and 3 (the bucket and the write key), 4 (`--maxzoom`), 6 (the dot over streets), 7 (whether invariant 2 covers counts of events), 8 (wide frames) and 9 (whether the public can reach staging). New or sharpened by this pass:

1. **Which Workers plan is the account on, and do you want a `[limits] cpu_ms` cap in `wrangler.toml`?** On Free the limit is 10 ms a request and a street draw would not fit. The repository does not say.
2. **Do you want drawn street layers kept at Cloudflare's edge, and by which store?** The Cache API (already used for venue images; a copy per data centre; may be unavailable behind Access) or Workers Cache (whole responses; new; changes billing for every route). Or neither until staging has numbers.
3. **After the load, will you put the object's etag in configuration** so a Worker refuses any other object under that key?
4. **What should one far-away event do to the landing's map?** Keep the frame fitted to every cell (today); fit it to the densest group and list the rest; or draw hexagons only below a chosen zoom. This is also the CCR's question 8.
5. **Should SharedReport draw streets under its map at all**, and if so at Mid and above only, as the map is today?
6. **Is a poster's block over legible streets wanted on the report, for a sponsor's read too?** The cell id is already in the answer.
7. **A rate limit on `/` and `/events`**: the route policy requires one and the code has none. The default for public reads is 60 in 10 seconds and 360 a minute an address. Is that the number for a page?
8. **Across the region's edge**, are streets on one side acceptable, or should such a frame draw hexagons only?
9. **Text and targets on the map at 320 px**: a town name is about 12 px and a dot's target is under 44 px. Larger marks, fewer marks, or no town names on a phone? Tokens are locked, so a colour answer is yours too.
10. **Should the area route take the reader's language for the credit?** It changes ADR-033's contract.
11. **The report page can still show a Google static-map thumbnail** in its dashboard mode (`shared-report.html:1504`). Remove it, or replace it with the base map?
12. **Invariant 3 says no `CF-IP*` header is read; the rate limiter reads `CF-Connecting-IP` to count requests.** Is the limiter's use the intended exception, to be written into the invariant?
