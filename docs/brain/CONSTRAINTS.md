## 4. Known Constraints

- **Admin auth**: CF Access JWT (JWKS-verified) + email allowlist; `X-OCR-Internal` and Bearer `ADMIN_KEY` fallbacks are env-flag-gated (staging). Phase 3 brings end-user auth.
- **HTML in Worker bundle**: 7 templates ship as separate Wrangler **text** modules (not inlined into `index.js`); upload is ~1.86 MB raw / ~413 KB gzip, of which `index.js` is 1.37 MB and `admin.html` 328 KB (measured 2026-09-30, `npm run measure:startup`). Served whole with per-request CSP nonces (Phase 1, moved to CDN in Phase 3). The older "carried on every invocation, so split it" argument is **superseded for startup CPU** — see the next bullet — but size, isolate memory and maintainability still argue for splitting admin.
- **The "three parallel frontend copies" line was wrong.** Only `src/templates/` holds templates. `web/shared/` is **live and load-bearing** — `testids.js` is generated by `scripts/gen-testids.mjs` (whose `--check` gates CI) and `assetState.js` is served over HTTP and asserted by smoke tests; **do not delete it**. `src/frontend/apiClient/` is 7 TS modules with no importer found — a retirement candidate, not a duplicate.
- **Infrastructure**: D1/KV/R2/zone provisioned (staging + production, real IDs in wrangler.toml); Firebase (Phase 3) not started. First staging deploy in flight (P1-7).
- **Multi-brand isolation**: `brand_id` in schema on core tables. **Corrected 2026-10-12:** this line said enforcement was list-level only and that object-level scoping was an open gap (OSE-1080). That was already out of date when it was moved here from CLAUDE.md §4. Object-level scoping exists: `guardAdminObjectScope` (`lib/admin-object-scope.ts`) runs in `router.ts` ahead of every `/api/v2/admin/events/:id/...` and poster-deployment by-id route, proves the object's `brand_id` is in the caller's set with a bound SQL predicate, fails closed, and answers 404 (never 403) on a miss. Gate: `workers/oursharedevents/tests/admin-object-scope.invariant.spec.ts` (22 tests). Public reads (`GET /api/v2/events/:id` and the public pages) are outside the guard by design. `AGENTS.md` (Architecture) carries the corrected sentence (owner confirmed 2026-10-22).
- **`@ocr/ui` is external and pinned**: it is not in this repo. Local dev needs the spine's `packages/ui` at `../packages/ui` (sibling of the checkout — clone the spine and symlink/copy it, or run `scripts/ci-stage-ocr-workspace.sh`), at the commit named in `.ocr-hub-ref`. CI fails with an `::error::` if the pinned spine cannot be fetched (needs `OCR_HUB_READ`, read-only, with no fallback to `OCR_PROPAGATE_TOKEN`; Dependabot runs get it from the Dependabot secret of the same name).
- **Spine pin, 2026-11-09:** `.ocr-hub-ref` is `9634fca` (spine #63, bumped from `b039d2f`, which #1034 took on 2026-10-23). #63 adds `.detail-card`, `.share-row`/`.share-chip` and `.sponsor-panel` to `@ocr/ui` for the digital poster (OSE-1825, OSE-1826), so the poster carries no CSS of its own for them. The other spine merges since `b039d2f` (#60 runner tooling archived, #61/#62 CI runners pinned to ubuntu-24.04) change no token, stylesheet or partial. Spine #56 added `backButton` and an outlined button to `@ocr/ui`; OSE still renders its own `lib/back-button`, not the spine's. The pin must be a commit on spine `main` (`tests/integration/hub-pin-ancestry.test.js`). Bump again only when a spine change reaches `packages/ui`.
- **`admin.html` keeps growing** (328 KB on 2026-09-30). **Startup cost measured (step 7a, `workers/oursharedevents/docs/ops/STARTUP-COST-2026-09-30.md`, `npm run measure:startup`): admin's effect on startup CPU is not measurable locally** (inside run-to-run noise; templates are text modules, never parsed as JS). **`h3-js` is ~85% of Worker startup CPU (≈20 of ≈25 ms locally) and requests a 32 MB heap at load** (local workerd; Cloudflare-side commit not verified). The cold-start lever is lazy-loading h3-js (a decision, pending) — it helps the QR-scan path, not the landing or `/api/v2/events/map`, which use h3. The admin split is argued on size, memory and maintainability, not startup CPU.
- **The under-5 floor is a fixed count, and two privacy gaps around it are open (2026-11-10).** (1) It is density-blind: 5 people in a rural res-9 cell are easier to name than 5 in a city block. `docs/adr/ADR-025-density-aware-resolution.md` (Proposed, OSE-1944) proposes coarser published resolution where census density is low; nothing is built, and it waits on the owner's choice of mechanism and the external reviewer's thresholds. (2) The BigQuery analytic layer (`oureventring_general`) has no privacy control of its own. `docs/adr/ADR-026-analytic-layer-privacy-jurisdiction.md` (Proposed, OSE-1946) proposes rules A to D. Only rule B is built (#1173, `40dd851d`): an event whose own count is withheld adds no one to the corridor baseline or the returns export (`PUBLISHED_EVENT_IDS_SQL`, `lib/shared-report.ts`). Rules A (who may read), C (noise, using the epsilon also owed to OSE-1780) and D (weekly baseline snapshots) are not built. No reader of the dataset exists yet, so the remaining exposure is latent.
- **A machine-read address is not reachable until the edge lets it through (2026-11-13, OSE-2022).** On stg the Cloudflare edge answers a non-browser read of `/events/:id/calendar.ics` and `/brands/:brand/calendar.ics` with a managed challenge, so the Worker never runs. Two things follow. (1) A calendar app cannot load either address until the owner decides `docs/adr/ADR-028-calendar-addresses-and-the-edge.md` (Proposed) and applies its rule; production was not checked. (2) A staging test must not count a challenge as a pass: use `scripts/ci/edge-read.mjs`, which sends `X-OCR-CI`, writes a warning for a challenged read, and fails it when the repository variable `CALENDAR_EDGE_STRICT` is `1` (unset today; the owner sets it after applying the skip rule, `docs/runbooks/RUNBOOK-STG-CI-SKIP-RULE.md`). Gate: `tests/integration/machine-read-edge-cover.test.js` fails when a `.ics` route in the router has no edge probe or no skip-rule cover. Older staging tests for other paths still accept a 403 from the edge as a pass; they were not changed.
