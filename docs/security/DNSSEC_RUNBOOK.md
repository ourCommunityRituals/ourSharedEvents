## 1. Purpose

Enable DNSSEC end-to-end to protect against DNS spoofing and cache poisoning attacks. This runbook covers enabling, validating, and rolling back DNSSEC for domains using Cloudflare as the DNS provider.

| Attribute | Value |
|-----------|-------|
| **Scope** | DNSSEC configuration for production domains |
| **Prerequisites** | Domain using Cloudflare DNS, registrar supports DS records |
| **Constraints** | Requires coordination between Cloudflare and domain registrar |

---

## 2. DNSSEC Overview

### 2.1 What DNSSEC Protects Against

| Threat | Without DNSSEC | With DNSSEC |
|--------|----------------|-------------|
| DNS cache poisoning | Vulnerable | Protected via cryptographic signatures |
| Man-in-the-middle DNS spoofing | Vulnerable | Protected via chain of trust |
| DNS response tampering | Vulnerable | Detected and rejected |

### 2.2 How DNSSEC Works

```
Root Zone (.)
    │ DS record points to →
    ▼
TLD Zone (.com)
    │ DS record points to →
    ▼
Your Domain (example.com)
    │ DNSKEY signs →
    ▼
DNS Records (A, CNAME, MX, etc.)
```

**Key Components:**
- **DNSKEY**: Public key published in DNS (generated by Cloudflare)
- **DS Record**: Hash of DNSKEY published at registrar (links to parent zone)
- **RRSIG**: Cryptographic signatures on DNS records

## 3. ENABLE — Implementation Steps

### Phase 1: Enable DNSSEC in Cloudflare

**Time Required:** 5 minutes

| Step | Action | Location |
|------|--------|----------|
| 1 | Log into Cloudflare dashboard | dash.cloudflare.com |
| 2 | Select the target domain | Domain dropdown |
| 3 | Navigate to DNS → Settings | Left sidebar |
| 4 | Locate DNSSEC section | Scroll to DNSSEC card |
| 5 | Click **Enable DNSSEC** | Blue button |
| 6 | Copy the DS record details | Save all fields shown |

**DS Record Details to Copy:**

```
┌─────────────────────────────────────────────────────────────┐
│  Key Tag:        [5-digit number, e.g., 12345]              │
│  Algorithm:      [number, typically 13 for ECDSA]           │
│  Digest Type:    [1=SHA-1, 2=SHA-256, 4=SHA-384]            │
│  Digest:         [long hexadecimal string]                  │
└─────────────────────────────────────────────────────────────┘
```

> **IMPORTANT:** Save these values. You will need them for the registrar.

### Phase 2: Publish DS Record at Registrar

**Time Required:** 5-15 minutes (varies by registrar)

#### Cloudflare Registrar (Automatic)

If your domain is registered with Cloudflare Registrar:
- DS record is published **automatically**
- No manual action required
- Skip to Phase 3 (Validation)

#### Other Registrars (Manual)

| Registrar | Navigation Path |
|-----------|-----------------|
| GoDaddy | My Products → DNS → DNSSEC → Add |
| Namecheap | Domain List → Manage → Advanced DNS → DNSSEC |
| Google Domains | DNS → DNSSEC → Manage DS records |
| Gandi | Domain → DNSSEC tab → Add DS record |
| Name.com | My Domains → Manage → DNSSEC |
| AWS Route 53 | Hosted zones → DNSSEC signing → Enable (if Route 53 is authoritative) |

**General Registrar Steps:**

```
[ ] 1. Log into registrar account
[ ] 2. Navigate to domain management
[ ] 3. Find DNSSEC or DS record settings
[ ] 4. Add new DS record with values from Cloudflare:
        - Key Tag: [paste from Cloudflare]
        - Algorithm: [paste from Cloudflare]
        - Digest Type: [paste from Cloudflare]
        - Digest: [paste from Cloudflare]
[ ] 5. Save/Submit the DS record
[ ] 6. Note: Propagation takes 10 minutes to 48 hours
```

### Phase 3: Wait for Propagation

| Stage | Typical Time | Maximum Time |
|-------|--------------|--------------|
| Cloudflare DNSSEC activation | Immediate | 5 minutes |
| DS record at registrar | 10 minutes | 24 hours |
| Global DNS propagation | 1 hour | 48 hours |

> **Do not proceed to validation until at least 1 hour has passed after adding the DS record.**

## 4. VALIDATE — Verification Methods

### 4.1 Quick Validation (Web-Based)

| Tool | URL | What It Checks |
|------|-----|----------------|
| DNSViz | https://dnsviz.net | Full DNSSEC chain visualization |
| Verisign DNSSEC Debugger | https://dnssec-debugger.verisignlabs.com | Chain of trust validation |
| DNSSEC Analyzer | https://dnssec-analyzer.verisignlabs.com | Comprehensive analysis |
| Cloudflare DNSSEC Test | DNS settings page in dashboard | Basic status |

**Recommended:** Use DNSViz for visual confirmation of the full trust chain.

### 4.2 Command-Line Validation

#### Check DS Record at Parent Zone

```bash
# Query the parent zone (TLD) for DS record
dig DS example.com +short
# Expected output: Key tag, algorithm, digest type, digest hash
# Example: 12345 13 2 A1B2C3D4...

# Verify against what Cloudflare shows
# Values should match exactly
```

#### Check DNSKEY at Authoritative Server

```bash
# Query for DNSKEY records
dig DNSKEY example.com +short
# Expected: Two keys (KSK and ZSK)
# KSK (257): Key Signing Key
# ZSK (256): Zone Signing Key
```

#### Verify DNSSEC Signatures (RRSIG)

```bash
# Check that records are signed
dig A example.com +dnssec +short
# Expected: IP address followed by RRSIG record

# Full DNSSEC validation
dig A example.com +dnssec +multi
# Look for "ad" flag (Authenticated Data) in response
```

#### Full Chain Validation with delv

```bash
# delv performs full DNSSEC validation
delv @8.8.8.8 example.com A +rtrace
# Expected: "fully validated"

# If not installed, use drill
drill -S example.com
# Expected: Shows chain from root to domain with [S] for secure
```

## 5. FAILURE MODES — Troubleshooting

### 5.1 Common Failure Scenarios

| Failure Mode | Symptoms | Root Cause | Resolution |
|--------------|----------|------------|------------|
| **DS Mismatch** | SERVFAIL responses, website unreachable for validating resolvers | DS record doesn't match DNSKEY | Verify DS values match Cloudflare exactly; re-copy and update at registrar |
| **Propagation Delay** | Works on some resolvers, fails on others | DS record not propagated globally | Wait up to 48 hours; check parent zone with `dig DS` |
| **Missing DS Record** | DNSViz shows broken chain at TLD | DS not published at registrar | Add DS record at registrar (Phase 2) |
| **Algorithm Mismatch** | Validation fails despite correct digest | Wrong algorithm number in DS | Verify algorithm matches (typically 13 for Cloudflare ECDSA) |
| **Stale DS Record** | Validation fails after key rollover | Old DS record still at registrar | Update DS record to match current Cloudflare DNSKEY |
| **NSEC3 Issues** | Some records fail validation | Misconfigured denial of existence | Contact Cloudflare support |

### 5.2 DS Record Mismatch Diagnosis

```bash
# Step 1: Get DS record from registrar/parent zone
dig DS example.com @a.gtld-servers.net +short
# Output: 12345 13 2 ABCDEF123456...

# Step 2: Get DNSKEY from Cloudflare
dig DNSKEY example.com @$(dig NS example.com +short | head -1) +short
# Output: 257 3 13 BASE64KEY...

# Step 3: Compute DS from DNSKEY (should match Step 1)
# Use online tool or dnssec-dsfromkey if available
```

**If values don't match:**
1. Copy fresh DS record from Cloudflare dashboard
2. Delete old DS record at registrar
3. Add new DS record at registrar
4. Wait 1 hour, re-validate

### 5.3 Propagation Delay Diagnosis

```bash
# Check if DS exists at TLD servers
dig DS example.com @a.gtld-servers.net +short
dig DS example.com @b.gtld-servers.net +short

# Check different public resolvers
dig A example.com @8.8.8.8 +dnssec  # Google
dig A example.com @1.1.1.1 +dnssec  # Cloudflare
dig A example.com @9.9.9.9 +dnssec  # Quad9

# If some work and some don't, propagation is still in progress
```

### 5.4 Emergency: DNSSEC Breaks DNS Resolution

**Symptoms:**
- Website unreachable from validating resolvers (8.8.8.8, 1.1.1.1)
- Website works from non-validating resolvers
- `dig` returns SERVFAIL with +dnssec flag

**Immediate Action:** See Section 6 (ROLLBACK)

## 6. ROLLBACK — Disabling DNSSEC

> **WARNING:** Incorrect DNSSEC rollback can cause extended DNS outages. Follow this order exactly.

### 6.1 Rollback Order (Critical)

```
┌─────────────────────────────────────────────────────────────┐
│  CORRECT ORDER:                                             │
│                                                             │
│  1. FIRST: Remove DS record at REGISTRAR                    │
│  2. WAIT: 24-48 hours for propagation                       │
│  3. LAST: Disable DNSSEC in Cloudflare                      │
│                                                             │
│  ⚠️  DO NOT disable Cloudflare DNSSEC before removing DS!   │
│     This will break DNS for all validating resolvers.       │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 Rollback Steps

#### Step 1: Remove DS Record at Registrar

**Time Required:** 5-15 minutes

| Registrar | Action |
|-----------|--------|
| Cloudflare Registrar | Dashboard → Domain → DNSSEC → Remove DS record |
| GoDaddy | My Products → DNS → DNSSEC → Delete |
| Namecheap | Domain List → Manage → Advanced DNS → DNSSEC → Delete |
| Other | Find DNSSEC settings, delete DS record |

```
[ ] Log into registrar
[ ] Navigate to DNSSEC/DS record settings
[ ] Delete/Remove the DS record
[ ] Confirm deletion
[ ] Note timestamp: ___________
```

#### Step 2: Verify DS Record Removal

```bash
# Check parent zone for DS removal
dig DS example.com +short

# Expected: Empty response (no output)
# If DS still appears, wait longer or check registrar

# Also check TLD servers directly
dig DS example.com @a.gtld-servers.net +short
```

**Wait Time:** Minimum 24 hours, recommend 48 hours

#### Step 3: Disable DNSSEC in Cloudflare

**Only after DS record is confirmed removed from parent zone:**

| Step | Action |
|------|--------|
| 1 | Log into Cloudflare dashboard |
| 2 | Select domain |
| 3 | Navigate to DNS → Settings |
| 4 | Click **Disable DNSSEC** |
| 5 | Confirm the action |

#### Step 4: Verify Rollback Complete

```bash
# Confirm no DNSSEC records
dig DNSKEY example.com +short
# Expected: Empty response

dig A example.com +dnssec
# Expected: Normal response without RRSIG

# Test resolution from validating resolvers
dig A example.com @8.8.8.8
dig A example.com @1.1.1.1
# Expected: Normal A record response
```

### 6.3 Rollback Checklist

```

PRE-ROLLBACK
[ ] Documented reason for rollback: _________________
[ ] Notified stakeholders of potential DNS disruption

STEP 1: REMOVE DS (REGISTRAR)
[ ] Logged into registrar
[ ] DS record deleted
[ ] Timestamp: ___________

[ ] 24 hours elapsed since DS removal

[ ] Verified at TLD servers: dig DS @a.gtld-servers.net +short returns empty

STEP 3: DISABLE CLOUDFLARE DNSSEC
[ ] Disabled in Cloudflare dashboard
[ ] Dashboard shows DNSSEC: Disabled

STEP 4: VERIFY
[ ] dig DNSKEY returns empty
[ ] dig A +dnssec returns no RRSIG

POST-ROLLBACK

[ ] Re-enablement plan documented (if applicable)

Completed by: _____________  Verified by: _____________
```

### 6.4 Emergency Rollback (DNS Completely Broken)

If DNSSEC misconfiguration has caused complete DNS failure:

**Option A: Fix Forward (Preferred)**
1. Verify DS record matches Cloudflare exactly
2. If mismatch, update DS at registrar to correct values
3. Wait for propagation (may take hours)

**Option B: Emergency DS Removal**
1. Remove DS record at registrar immediately
2. DNS will recover within 1-48 hours as DS propagates
3. Do NOT touch Cloudflare DNSSEC settings during this time
4. After DS fully removed (48 hours), then disable Cloudflare DNSSEC if needed

**Mitigation During Outage:**
- Provide users with direct IP addresses if critical
- Temporary hosts file entries for critical systems
- Monitor propagation with `dig DS` queries

## 7. Ongoing Operations

### 7.1 Key Rollover (Automatic)

Cloudflare handles DNSSEC key rollovers automatically:
- ZSK (Zone Signing Key): Rolled periodically
- KSK (Key Signing Key): Rolled when necessary

**No manual DS record updates required** for routine key rollovers when using Cloudflare.

### 7.2 Monitoring Recommendations

| Check | Frequency | Method |
|-------|-----------|--------|
| DNSSEC status in Cloudflare | Weekly | Dashboard visual check |
| DNSViz full chain | Monthly | https://dnsviz.net |
| DS record presence | Monthly | `dig DS domain.com +short` |
| Validation from public resolvers | Monthly | `dig A domain.com @8.8.8.8 +dnssec` |

### 7.3 Alerts to Configure

| Alert | Tool | Purpose |
|-------|------|---------|
| DNSSEC validation failure | Third-party monitoring (e.g., Pingdom, Datadog) | Detect chain breakage |
| DNS resolution failure | Uptime monitoring | Detect complete outage |
| Certificate transparency logs | SSLMate Cert Spotter | Detect potential hijack |
