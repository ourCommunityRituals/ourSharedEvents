The operating contract for every coding agent in this repo (Claude Code, Copilot, Codex, others) and for people. It holds what stays true; history and status live in `docs/brain/`. Keep it under 12 KB: `tests/integration/agent-instructions-budget.test.js` fails above that.

OSE is one product in the OurCommunityRituals (OCR) line: event infrastructure, API and admin. The org vision is `OCR-docs/docs/VISION.md`; this file governs OSE only.

## Architecture

- One Cloudflare Worker + D1 (`workers/oursharedevents/`). Surfaces: admin, public event page, `/events`, display (TV), poster, SharedReport, sponsor home, form pages. Templates are Wrangler text modules served with per-request CSP nonces.
- **Two databases, never crossed:** `DB` is the anonymous public side (events, sponsors, scans, audit log); `FORMS_DB` is the identified side (registrations, check-ins, surveys, email sign-ups, flags, PII audit). Gate: `workers/oursharedevents/tests/architecture.spec.ts`.
- **Runtime is LLM-free:** no model-provider SDK or API URL under `src/`. The only sanctioned AI seam is `src/lib/ai-sanitization.ts` (dormant, CODEOWNERS-locked). Gate: `tests/e2e/0-architecture/runtime-llm-free.invariant.spec.ts`.
- Admin auth: Cloudflare Access JWT (JWKS-verified) + allowlist; `X-OCR-Internal` / Bearer `ADMIN_KEY` fallbacks are env-gated (staging). Every admin request that is not GET/HEAD/OPTIONS passes `lib/admin-write-guard.ts` (same-origin or key actor, JSON body only). In a worker test, an email actor that writes sends `'Sec-Fetch-Site': 'same-origin'`.
- **Brand scoping is list-level only:** get and update by id are not brand-checked yet (OSE-1080). Do not assume object-level isolation in a new handler.
- Public reads are rate-limited at the route (`lib/public-read-limit.ts`); public event responses are an allowlist (`lib/public-event-projection.ts`), never a spread of the row.
- `web/shared/` is live: `testids.js` is generated by `scripts/gen-testids.mjs` (its `--check` gates CI) and `assetState.js` is served. Never delete it.
- `@ocr/ui` lives in the hub repo, pinned to an exact hub commit (on hub `main`) in `.ocr-hub-ref`; bump the pin in a PR. Local dev needs the hub's `packages/ui` at `../packages/ui` (`scripts/ci-stage-ocr-workspace.sh`). More in `docs/brain/CONSTRAINTS.md`.

## Invariants (owner decisions; do not reopen)

1. **Never who, only how many.** Publish counts, never identities. Presenters who opt in are the only exception.
2. **The under-5 floor has no exceptions:** a published count below 5 is withheld, for a brand's own admin too and at every tier. Totals and rates use `lib/count-floor.ts` (`floorTotalOfParts`, `flooredRatePct`). A withheld count reads in words ("Fewer than 5"), never as 0. Open gaps: OSE-1656 (some counts an admin still reads exactly), OSE-1652.
3. **Place, not person:** location is an H3 cell, res 7 (the area a link was published into) or res 9 (a physical placement), never request geo or IP; no `CF-IP*` header is read. Public reads refuse coordinate-shaped input (`/api/v2/events/map`); admin placement writes take coordinates only to derive the cell.
4. **No cookies on public surfaces.** Geolocation picks what to show and is never stored.
5. **The display shows no counts.** The public check-in answer carries no count; counts are post-event.
6. **Sponsors need two-sided consent:** a sponsor shows only when it accepted and the organizer accepted (`SPONSOR_ON_SHOW_SQL` in `lib/sponsor-card.ts`). On a page that shows an event title, the sponsor strip sits below the title and date and above the content and map.
7. **Security is never tier-gated:** audit, roles, isolation and retention are the same at every tier. Templates never gate; tiers gate features.
8. **Design system:** colours only from `packages/tokens` (hub); never a raw hex in a page; never change colours in `packages/ui`. One `<h1>` per page; touch targets ≥ 44 px; input text ≥ 16 px.
9. **PII** is encrypted and scrubbed in `lib/forms-db.ts` / `lib/pii.ts`; forms tables store a per-event keyed id, never the raw anonymous id.

## Quality gates

- **Born red:** every new test, check or gate is watched failing on an injected fault before it is trusted. A gate that cannot fail counts as absent.
- **Coverage is what CI runs.** A `tests/e2e/` or Playwright spec counts only if a workflow names it; a Bruno run counts only if its `test()` names print.
- Every case at two layers: the workers-pool mock layer and staging (Bruno / Playwright).
- A new structural invariant spec must be listed in the T0 `invariants` step (`tests/integration/infra-consistency.test.js` enforces it).
- Run lint and tests locally before pushing. Each push cancels the running OSE CI run, so batch review fixes into one push.

## Human approval (an agent never does these)

- **Production:** deploys only through CI (tag or `deploy_production=PRODUCTION` dispatch). No workstation `wrangler deploy`, remote D1 writes or production changes.
- **Secrets:** never in chat or logs, never read from credential files; the owner sets them in their own terminal. A secret that reaches a transcript is rotated.
- **Repository controls:** branch protection, rulesets, runners, repo secrets and variables, `--admin` merges, force pushes.
- **Destructive data steps:** D1 Time Travel restores; deleting databases, buckets or namespaces (break-glass runbooks only).

This binds every agent. For Claude Code, `.claude/hooks/policy-gate.mjs` blocks most of it where the owner has installed it (it matches command text and fails open). **A model's confidence, a CCR score included, is a signal, never permission;** required checks and the PO are the authority.

## Production posture: in sync, and closed (owner, 2026-10-12)

Staging and production stay **in sync and ready for each other**. The one difference in posture is the **live switch, and it is off**: production is closed to the outer network.

- **In sync** means the same code (the SHA that passed the staging chain), the same migration level on both databases, and the same binding shapes, with every intentional difference listed in `wrangler.toml` and nothing else. Updating production (migrations, a CI deploy) is allowed when the owner asks; it keeps production ready and does not make it live.
- **Closed** means no `PRODUCTION_LIVE`, no announcing, no clients, and no step that makes production reachable from the outer network. An agent never sets `PRODUCTION_LIVE`, never proposes a go-live sequence as the plan, and never treats a deploy as a launch.
- **What is true today:** there is no code switch that closes the production host. The Worker answers on `oursharedevents.com` (read live 2026-10-03). Closing it is an edge setting the owner makes (an Access policy over the whole production host, OSE-1353 / OSE-1377), not something a PR can claim. Until that is set, say "held, not closed" and do not call production dark.
- **What is not enforced yet:** nothing in CI compares staging and production continuously. `scripts/compare-environments.js` is from the Apps Script era and fails on a missing root `wrangler.toml`; `scripts/prod-preflight.mjs` checks the checkout and saved readings only. Until a parity gate exists, production is in sync only on the day someone reads both.
- **Slow and steady: align fully, then announce.** Both environments are brought fully aligned before production availability is announced. Once they are, the owner may turn the live switch on to support customers. Not before, and not as a way to reach alignment. What "fully aligned" needs is the owner's call; a proposed bar, for the owner to accept or change: the production Worker runs a SHA that passed the staging chain; both production databases are at the migration level the code requires; production bindings are real and not shared with staging; the only differences between the two are the listed intentional ones; production smoke passes while the host is still closed.
- **The Done bar** is the staging chain while production is held closed. The "after first launch" line below applies only if the owner takes production live.

## Definition of Done: two stages (OSE-1443)

- **Merged** (Linear: In Progress): on `main`; levels 1–5 ran on the PR; a named CI job goes red if it regresses.
- **Done** (Linear: Done): merged **and** the post-merge staging chain is green for the merge SHA, or a later `main` SHA containing it. All four jobs must be `success`: `T1 Deploy → Staging`, `T2 Contract → Staging (Bruno)`, `T3 E2E Smoke → Staging (Playwright)`, `T4 Functional → Staging`.
- The full pyramid, no partial pyramids: security (XSS, injection, auth boundaries), lint, contract (API shape, D1 schema parity), unit, integration (Worker D1 + forms security), API (Bruno on staging), E2E (Playwright).
- A CI/CD testing ticket is attached to the story.
- After first launch (`PRODUCTION_LIVE`), production deploy + smoke join the Done bar. Production is held closed (owner, 2026-10-12), so today the bar is the staging chain.
- Keep Linear matched to `main` with evidence comments (owner, 2026-10-06: no need to ask first): In Progress at merge; when T1–T4 are green for the merge SHA, comment the run id and move it to Done. If any part cannot be verified from code or CI (owner actions, other repos), move it to In Review and say what was not verified. Check with `gh run list --workflow "OurSharedEvents CI/CD" --branch main --event push`, then `gh run view <id> --json jobs`.

## Pull requests (Linear close-guard)

- A merge never closes a story by itself. Use `Part of OSE-###` in the PR body; keep ids out of the branch name and title.
- Keep closing words (close, fix, resolve, complete, implement) away from ids in the body **and** in commit messages (a squash copies them to `main`). `scripts/check-pr-linear-close.mjs` fails a PR that breaks this. Only a PR that finishes a story says `Closes OSE-###`.
- Copilot-authored PRs wait for a human CI approval by design (ADR-020).

## Reviews: CCR

Code and PR reviews, security and architecture assessments, readiness and test-gating decisions use CCR (Critical, Conservative, Recursive): loops run in order, a weighted score (`100 − Σ finding × 25/15/10/5/2`, plus the protocol's modifiers), a 95% gate, and a human gate below it. Security Critical findings get no partial credit. **Changes to this file, CLAUDE.md, STORIES.md or the protocol need 5+ loops with a human gate after every loop.** Worksheets go in `.claude/outputs/CCR-<topic>-<date>.md`. Protocol: `.claude/skills/ccr/SKILL.md` → `.claude/skills/ccr-protocol.md`.
