# Event lifecycle audit — create → list → drafts → manage → expiry

**Date:** 2026-09-16 · **Scope:** `workers/oursharedevents` (OSE) · **Trigger:** "once the event is created there's no way to come back and see it in a list, find my drafts, manage them, or have stale drafts killed off."

## What was found

The flows were connected. The state machine had no driver.

1. **Every UI-created event was stuck as a draft.** Both create paths (wizard `createEvent()` and the dashboard form) POST with no `status`, so `handleCreateEvent` writes `draft`. No control anywhere in `admin.html` moved an event to `ready` or `active`. The only activation route was `POST /verify-qr` (`ready → active`), and nothing set `ready`. Meanwhile `/events/:id`, the poster, and the display all refuse drafts (`RENDERABLE_SURFACES.draft = ['admin']`). The wizard's step 5 said "🎉 is ready to go" and handed out `/events/:id` links that rendered the branded 404 ("this link doesn't work anymore").
2. **The list existed but was hard to reach and blunt.** "All Events" lived only behind "Show me everything"; the front door offered Create a sponsor / Create an event / full dashboard, never "your events". No status filter, no "mine" (nothing on `events` recorded the creator), and a silent cap at the API's default `limit=50` with no page-two (the API already paged; the UI never asked).
3. **No draft expiry.** The 3 AM cron ran six lifecycle jobs; none touched abandoned drafts.
4. **`PUT status` bypassed the state machine.** `handleUpdateEvent` accepted any → any (`draft → active`, `archived → active`), while `verify-qr` / `unverify-qr` enforced `VALID_TRANSITIONS`. Two doors, one lock.

## What is deliberately NOT in this slice

- **Delete from the list.** `DELETE /api/v2/admin/events/:id` exists (scan-guarded, OSE-982) but the panel offers Archive, not Delete. Archive is reversible; a stray tap on a phone should not be able to destroy a row. Add a Delete-with-confirm only if archived rows pile up.
- **Sorting by upcoming date.** The list still orders by `created_at DESC` (the cursor key). A "next up first" sort is a separate cursor design.
- **Wizard "Basic" mode.** Per the 2026-08-20 decision, Advanced first; the wizard just stops lying.
- **Object-level `created_by` authorization.** `mine` is a filter. Brand membership remains the permission boundary (OSE-666 / OSE-1080).

## How to verify on staging

1. Wizard → create an event → step 5 shows "saved as a draft" → **Go live now** → open the public link from step 4; it renders.
2. `/admin` → **Your events** → **Drafts** chip shows only drafts; **Only mine** narrows to your email's rows; **Show more** appears past 50.
3. Select a live event → status panel → **Take offline** → public link now 404s → **Go live** → renders again.
4. `curl -X PUT .../admin/events/:id -d '{"status":"active"}'` on a draft → `409 INVALID_TRANSITION`.
5. Set `DRAFT_EXPIRY_DAYS=1` on staging, seed a draft with `updated_at` two days back, trigger the cron → row is `archived`, one `DRAFT_EXPIRY` audit row lists its id, it appears under the **Archived** chip and **Reopen as draft** brings it back.
